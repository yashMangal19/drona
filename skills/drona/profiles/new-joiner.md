# Profile: new joiner

Someone new to a team, learning its platform, codebase or domain to a ramp-up date.

## Defaults

| | |
|---|---|
| Deadline | The ramp-up date, or 4–6 weeks from start if none is set. |
| Exam | What a senior on the team would ask: explain a flow end to end, ship a small change, answer follow-ups. `goal.exam` names the first real task they should own. |
| Pace | Fit around working hours; blocks of 50/10 inside the workday where the team allows it. |
| Tone | Practical, curious, senior-to-junior. |

## Intake extras

- The first real task they will own. Build the tree backwards from it.
- Which parts are public (language, framework, protocols) and which are team-specific. Teach public parts from public sources; for team-specific parts, point to the team's own docs and people.
- Keep anything confidential out of the notes unless the learner's folder is allowed to hold it.

## Exam

Senior-style follow-ups: "walk me through what happens when…", "why is it built this way?", "what breaks if…?". Hands-on checks are a small real change or a trace through the real system.

## Hands-on

Read and trace real code, then make a small change; for public fundamentals, a toy version built from scratch.

## Humans

A buddy or senior reviews one hands-on piece per layer and answers team-specific questions. The examiner flags every claim about the team's system that it cannot verify.
